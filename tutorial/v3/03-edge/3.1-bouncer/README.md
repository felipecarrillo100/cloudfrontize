# 3.1 The Bouncer

## 🎭 The Scenario
Your `/admin/` dashboard is public. You need a quick layer of security with Basic Auth, without changing your backend code, and **without** putting a password on the public gallery.

## 📖 The Lesson: Cache Behaviors and Short-Circuiting

### Cache behaviors
A CloudFront distribution has a **default behavior** and, optionally, **cache behaviors** for specific path patterns. CloudFront matches each request against the path patterns in order, and the first match decides:
- which **origin** the request goes to, and
- which **functions** run on each event (viewer request, origin request, origin response, viewer response).

So to protect only the admin area, attach the Bouncer to a `/admin/*` behavior instead of the default behavior. The public pages never run it.

> [!NOTE]
> The behavior is chosen from the URI the **viewer** asked for, before any function runs. If a function rewrites the URI, the request stays on the same behavior and origin: *"If a function changes the URI for a request, that doesn't change the cache behavior for the request or the origin that the request is forwarded to."*

### Short-circuiting
If a Lambda@Edge function returns a **response** instead of the request, CloudFront sends that response straight back to the viewer. The request never reaches the cache or the origin. That makes viewer-request the right place for a gatekeeper:
1. **Unauthorized users never touch your servers.**
2. **The rule applies at the edge**, close to the user, before the request crosses the network to your origin.

### Basic Auth
Basic Auth is a simple challenge and response. Without valid credentials, return `401 Unauthorized` with a `WWW-Authenticate: Basic` header; the browser then shows a login prompt and sends the credentials back in an `Authorization` header.

> [!TIP]
> For the event JSON and how to generate a response, see the [Lambda@Edge Event Structure Guide](../../../commons/lambda-at-edge-event.md).

## 🎯 Your Goal
For requests under `/admin/`, check the `Authorization` header. If it's missing or wrong, return `401 Unauthorized` from the edge. The credentials for this exercise are `admin` / `password`.

To practice, replace the body of `viewer-request.bouncer.js` with this starter code:

```javascript
'use strict';

exports.handler = async (event) => {
    const request = event.Records[0].cf.request;
    const headers = request.headers;

    // TODO: compare headers.authorization with "Basic " + base64("admin:password")
    // and return a 401 response with a WWW-Authenticate header when it doesn't match.

    return request;
};
```

## 🛠️ Run It
From this folder:
```bash
cloudfrontize validate
cloudfrontize --webui
```

## 🧪 How to Test

### 1. With `curl`
```bash
curl -i http://localhost:3000/                                  # 200: the public gallery
curl -i http://localhost:3000/admin/index.html                  # 401 + WWW-Authenticate: Basic
curl -i -u admin:password http://localhost:3000/admin/index.html  # 200: the dashboard
```

### 2. In a browser
Open `http://localhost:3000/admin/index.html`: the browser asks for a username and password.

### 3. In the WebUI
Open `http://localhost:3001` and expand an `/admin/` request. The journey ends at **[L@E: viewer-request]** with status `401`: the origin was never contacted. A request for `/` shows no function at all.

## 💡 Fidelity Tip
A response generated by a **viewer** event is limited to **40 KB**, headers and body included (1 MB for origin events). Run with `"strict": true` in `cloudfrontize.json` and CloudFrontize returns a **502** for anything larger, as CloudFront does.
